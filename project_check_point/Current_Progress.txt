1. Original assessment and production decisions
- Original implementation: src/pipeline.py.
- Dataset: 8,693 training rows and 4,277 Kaggle test rows.
- Original HistGradientBoosting baseline:
  * 5-fold CV accuracy: 0.8036 (+/- 0.0093)
  * Holdout accuracy: 0.8079
- Identified preprocessing leakage in the original script because learned
  imputation/encoding happened before validation splits.
- Identified training-serving skew in GroupSize and group-based imputation.
- Removed GroupSize and the raw group ID from version one so a passenger receives
  the same preprocessing alone or in a batch.
- Retained row-based GroupMemberNumber from the PassengerId suffix.
- Kept CabinNumber as a numeric ship-location feature.
- Kept the domain rule that a missing individual spending value contributes zero
  when calculating TotalSpend. A real zero remains a real zero.

2. Repository hygiene and package structure
- Added .gitignore rules for caches, environments, local secrets, artifacts,
  macOS files, notebook checkpoints, and local Kaggle CSV files.
- Stopped tracking .DS_Store and data/*.csv while preserving the local files.
- Added the src/spaceship_titanic package, scripts, tests, api, app, and artifacts

- Added pytest.ini with src on the test import path.

3. Deterministic feature engineering
File: src/spaceship_titanic/features.py

engineer_features:
- Copies its input instead of mutating raw data.
- Splits Cabin into Deck, numeric CabinNumber, and CabinSide.
- Extracts numeric GroupMemberNumber from PassengerId.
- Calculates TotalSpend from RoomService, FoodCourt, ShoppingMall, Spa, and
  VRDeck, treating missing components as zero for this calculation.
- Handles one-row requests and missing identifiers safely.

4. Complete leakage-safe sklearn Pipeline
File: src/spaceship_titanic/model.py

The pipeline contains:
- FunctionTransformer(engineer_features, validate=False).
- ColumnTransformer with feature-specific policies:
  * Age: median imputation learned from the current training fold.
  * Five spending columns: constant-zero imputation.
  * Categorical fields: most-frequent imputation followed by
    OneHotEncoder(handle_unknown="ignore", sparse_output=False).
  * CabinNumber, GroupMemberNumber, and TotalSpend: passed through unchanged.
  * Unused raw fields such as Name, Cabin, and PassengerId: dropped after their
    engineered information is extracted.
- HistGradientBoostingClassifier(random_state=42).

Important revised decision:
- A single median imputer is NOT used for every numeric field. The student
  correctly challenged that design because median CabinNumber and median
  GroupMemberNumber are not meaningful domain substitutions.
- HistGradientBoosting handles the 199 missing CabinNumber values natively.
- GroupMemberNumber and TotalSpend have no missing values in the current training
  data, so they pass through unchanged.

5. Leakage-safe training and evaluation
File: scripts/train.py

- Creates a reproducible, stratified 80/20 train/holdout split.
- Runs shuffled 5-fold StratifiedKFold cross-validation on the training portion.
- Fits the entire pipeline inside every fold so learned preprocessing never sees
  that fold's validation rows.
- Reports accuracy, precision, recall, F1, ROC-AUC, and confusion-matrix counts.

Verified metrics on 2026-10-17:
- Training rows: 6,954
- Holdout rows: 1,739
- Fold accuracies:
  [0.80373832, 0.80877067, 0.80014378, 0.80589504, 0.80287770]
- Mean CV accuracy: 0.8043
- CV standard deviation: 0.0029
- Holdout accuracy: 0.8137 (1,415 / 1,739 correct)
- Holdout ROC-AUC: 0.9120
- Confusion counts:
  * True negatives: 703
  * False positives: 160
  * False negatives: 164
  * True positives: 712
- Precision, recall, and F1 are approximately 0.81 for both classes.
- Compared with the old pipeline, average accuracy is essentially preserved while
  preprocessing is now leakage-safe, batch-independent, and deployable.
